# TreeDetector

TreeDetector is a command-line research project for preparing a fixed UAV tree-crown dataset and benchmarking instance-segmentation models. It currently supports Ultralytics YOLO segmentation and generic Detectron2 Mask R-CNN (`mask_rcnn_R_50_FPN_3x`). Both adapters use the same canonical split so their results can be compared. Source images and annotations are treated as read-only.

## Repository structure

- `main.py` — command-line entry point.
- `src/dataset/` — annotation readers, validation, deterministic splitting, YOLO export, and COCO export.
- `src/models/` — YOLO and Detectron2 model adapters.
- `src/benchmark/` — training/evaluation orchestration and result comparison.
- `src/utils/` — logging and reproducibility helpers.
- `tests/` — unit tests that do not require training.
- `config/config.example.yaml` — portable configuration template.
- `docs/model_notes.md` — model implementation notes.
- `datasets/`, `runs/`, and `results/` — local generated data and artifacts; their contents are intentionally excluded from Git.

## Python and environment policy

The existing local virtual environment was created with Python 3.11.9, so Python 3.11 is the known working version. Keep two separate environments: one for YOLO and one for Detectron2. Do not install both model stacks into one environment simply to make setup shorter.

The dependency files contain direct project dependencies rather than a dump of the current machine:

- `requirements.txt` — shared data-processing dependencies.
- `requirements-yolo.txt` — shared dependencies plus PyTorch and Ultralytics.
- `requirements-detectron2.txt` — shared dependencies; PyTorch and Detectron2 are installed separately because their compatible build depends on OS and CUDA.
- `requirements-dev.txt` — dependencies needed to run the tests.

## Configuration and external dataset

Create the machine-local configuration after cloning:

```powershell
Copy-Item config/config.example.yaml config/config.yaml
```

Edit each `images_dir` and `annotations_dir` in `config/config.yaml` to point to the source image/annotation folders on that PC. Keep each dataset `id` stable because it is used for provenance. The current benchmark output is expected at:

```text
datasets/benchmark_v4
```

`benchmark_v4` is a generated canonical dataset, not a repository dependency, and is excluded from Git. Either copy the existing local `datasets/benchmark_v4` directory to the new PC out of band, or copy the original source datasets, update the paths in `config/config.yaml`, and run `python main.py prepare`. With `copy_mode: copy`, preparation copies normalized images into the benchmark directory; it does not modify the source data.

The local `config/config.yaml` is excluded because it contains machine-specific paths. The committed example retains the current benchmark settings but uses placeholder paths.

## YOLO environment setup (Windows PowerShell)

```powershell
conda create -n treedetector-yolo python=3.11 -y
conda activate treedetector-yolo
python -m pip install --upgrade pip
```

Install the PyTorch build appropriate for the PC first, using the command generated by the PyTorch installer for either CPU or the installed CUDA runtime. Then install the YOLO dependencies:

```powershell
pip install -r requirements-yolo.txt
pip install -r requirements-dev.txt
```

The inspected environment used `torch 2.11.0+cu128`, `torchvision 0.26.0+cu128`, and `ultralytics 8.4.126` on Python 3.11.9. Those versions record the known local environment but are not hard pins: a new PC must use a PyTorch/CUDA combination supported by its NVIDIA driver. The configured `yolo11m-seg.pt` is intentionally excluded from Git; Ultralytics can download the standard checkpoint when it is first requested, or you can copy the local file separately. The local `yolo26n.pt` is also excluded and is not referenced by the current configuration.

## Detectron2 environment setup

Detectron2 remains a separate environment. Native Windows Detectron2 builds are not consistently available; WSL2/Linux is generally the more reproducible route. If using WSL2, run the following in its shell (paths and activation syntax will be Linux-style):

```powershell
conda create -n treedetector-detectron2 python=3.11 -y
conda activate treedetector-detectron2
python -m pip install --upgrade pip
pip install -r requirements-detectron2.txt
```

Next install a mutually compatible `torch`/`torchvision` pair for the intended CPU or CUDA runtime, then install Detectron2 from its official source as used by the existing project workflow:

```powershell
pip install "git+https://github.com/facebookresearch/detectron2.git"
pip install -r requirements-dev.txt
```

For native Windows, follow Detectron2's source-build instructions and use matching Visual C++ build tools, PyTorch, torchvision, and CUDA versions. A Detectron2 build compiled for a different PyTorch or CUDA version may import unsuccessfully. Detectron2 is optional for YOLO commands; a missing installation produces a focused error only when the Detectron2 adapter is selected.

CUDA is selected automatically when `torch.cuda.is_available()` is true; otherwise the code uses CPU. On GPU memory errors, reduce `detectree2_training.ims_per_batch`, image resolution, or `roi_batch_size_per_image` in the local config.

## Verify the installation

From the repository root, with the intended environment activated:

```powershell
python --version
python main.py --help
python main.py info
python -m pytest
```

`python main.py info` reports Python, PyTorch, CUDA, GPU, selected YOLO weights, and prepared split counts. Before the dataset exists, zero split counts are expected. For a direct CUDA check:

```powershell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

In the Detectron2 environment, also verify:

```powershell
python -c "import detectron2, torch; print(detectron2.__file__); print(torch.__version__)"
```

## Prepare the benchmark dataset

The project accepts YOLO detection/segmentation TXT, polygon COCO JSON, and LabelMe polygon JSON annotations. After configuring the external source directories:

```powershell
python main.py prepare
```

This validates annotations, creates or reuses deterministic train/validation/test splits, writes `datasets/benchmark_v4/dataset_manifest.csv`, exports YOLO labels and COCO annotations, and generates dataset statistics. Existing manifest splits are reused. Set `dataset.rebuild_split: true` only when intentionally replacing the benchmark split.

## Training, evaluation, prediction, and benchmarks

These are the commands exposed by the existing CLI:

```powershell
python main.py train --model yolo
python main.py train --model yolo --experiment runs/yolo_seg_YYYYMMDD_HHMMSS_xxxxxx
python main.py evaluate --model yolo --experiment runs/yolo_seg_YYYYMMDD_HHMMSS_xxxxxx
python main.py predict --model yolo --experiment runs/yolo_seg_YYYYMMDD_HHMMSS_xxxxxx
python main.py predict --model yolo --experiment runs/yolo_seg_YYYYMMDD_HHMMSS_xxxxxx --source "D:/images/example.jpg"
python main.py benchmark --model yolo
```

Passing an existing YOLO experiment to `train` resumes from its newest `last.pt` checkpoint.

Activate the separate Detectron2 environment for these commands:

```powershell
python main.py train --model detectree2
python main.py evaluate --model detectree2 --experiment runs/maskrcnn_detectron2_YYYYMMDD_HHMMSS_xxxxxx
python main.py benchmark --model detectree2
python main.py benchmark --model all
python main.py compare
```

`--model all` requires both implementations to be importable in the active environment, so with the deliberately separate environments it is usually clearer to run each model's benchmark in its own environment and then run `python main.py compare` against the shared results.

Training checkpoints, predictions, metrics, plots, logs, and benchmark CSV files are written below `runs/` and `results/`. They are intentionally excluded from Git. Copy any run needed for later evaluation to the new PC separately or store it in an external artifact service.

## Annotation and split notes

YOLO TXT and LabelMe JSON files match images by stem. Empty annotation files are valid zero-tree images. Missing/orphan labels, corrupt images, invalid classes or coordinates, zero-area boxes, invalid polygons, and duplicate filenames are reported to `results/dataset_validation.csv` and prevent export. COCO RLE masks are not decoded; polygon segmentation is supported.

The supplied configuration excludes complete images containing the label `zmladenie` or LabelMe `circle` geometry. The source files are never changed. Random image splitting can leak information when adjacent UAV frames overlap; grouped/spatial split strategies are extension points but are not currently implemented.
