# Mask2Former implementation plan

YOLO is the only active backend. Detectron2 / Mask R-CNN was abandoned due to legacy build/toolchain complexity; the safety commit retains its implementation. No packages were installed and no Mask2Former execution is implemented.

1. **Environment:** recommend a separate Python 3.11 environment, with a compatible GPU PyTorch/torchvision pair and pinned dependencies after a smoke test. Preserve `.venv-yolo`. Current [Transformers installation documentation](https://huggingface.co/docs/transformers/main/installation) lists Python 3.10+ and PyTorch 2.5+; verify stable package and driver compatibility when implementing.
2. **Framework:** use Hugging Face Transformers `Mask2FormerForUniversalSegmentation` and its image processor. This is a proposed choice supported by its [Mask2Former API](https://huggingface.co/docs/transformers/model_doc/mask2former) and [instance segmentation training example](https://github.com/huggingface/transformers/blob/main/examples/pytorch/instance-segmentation/run_instance_segmentation.py). Choose and record the pretrained checkpoint and backbone before training.
3. **Dataset adapter:** reuse the existing manifest, fingerprint and COCO JSON directly, without export or resplitting. There are 115/25/25 images and 2063/446/492 instances in train/val/test. All JSON image paths resolve on this Windows machine; remap absolute paths in memory on another machine or WSL. COCO category 1 is tree and 2 is TreeGroup; map to training labels 0/1 and invert for evaluation. Rasterize each polygon into a separate binary instance mask, preserving overlaps and empty images; provide mask/class labels and padded batches. IDs are split-local. Verify image dimensions, IDs, counts and fingerprint before loading.
4. **Training:** implement `src/models/mask2former_model.py` against `BenchmarkModel`, including metadata and parameter count, then register it and add an explicit disabled configuration section. Only then expose `--model mask2former`. Save config, dependency versions, checkpoint identity, seed, dataset fingerprint, timings and checkpoint selection criteria in a new run directory.
5. **Validation/test:** train on train only; select checkpoint and tune thresholds using validation only. Evaluate the frozen checkpoint on test once. Existing `evaluate()` is test-oriented, so validation selection belongs in the new trainer. Do not use test for hyperparameter selection.
6. **Metrics:** export scored per-instance predictions at original image resolution as COCO RLE, with image/category IDs, then use pycocotools COCOeval with `iouType=segm`. Report AP50 and AP across IoU 0.50:0.05:0.95 overall and per class, normalizing percent versus fraction consistently. Record max detections, area ranges and evaluator versions. Reuse existing CSV fields and experiment logging. Ultralytics native AP and COCOeval AP are not automatically equivalent; later evaluate both models with the same COCO evaluator in separate output directories while retaining the completed native results.
7. **Visualization:** reuse deterministic test-image sampling and OpenCV contour/box drawing concepts. Current YOLO prediction code and `predict_mask_contours.py` depend on Ultralytics results, so they need a neutral mask/box/score representation before reuse. Postprocess Mask2Former instance outputs to original image sizes and save into its own run.
8. **Fair comparison:** freeze the shared split, class mapping, annotations and seeds. Record backbone, pretraining data, resize policy, augmentation, training budget, hardware, parameter count and model size; match evaluation settings and timing protocol. Current elapsed evaluation includes more than pure inference, so use a separate warmup and synchronized timing protocol for a speed comparison. Preserve the existing 640-pixel YOLO setting and document any Mask2Former resolution difference. Never overwrite the completed YOLO run.
